# BLUE 3.0.4beta · 图纸工坊

**BLUE** = Blueprint Layout & Usage Engine（图纸工坊）：创建图纸、在流程里使用图纸。

用图纸把皮肤原图裁成选区、贴到画布上合成，再按 Result 的命名模板导出。

- 作者：B 站 **拾贰Tuenztoo_**；交流 QQ：**2382488749**
- 用 DeepSeek 开发的免费项目；本次开发耗费 ¥18.67
- 运行：`python skin_head_gui.py`
- 依赖：`pip install pillow`
- 首次运行会自动建 `workflows/`、`blueprints/`，并带上自带的默认流程和默认蓝图「基础」（3 个 Result，示例图一起打包）。
- 版本：**3.0.4beta**
- 文字介绍：[BLUE介绍.md](BLUE介绍.md)；完整 Wiki：[WIKI.md](WIKI.md)
- 系统要求：**Windows 10 / 11**（当前 exe 用 Python 3.12 打包）。Windows 7 需要单独用 Python 3.8 构建的兼容版，直接跑会提示缺少 `api-ms-win-core-path-l1-1-0.dll`。

## 流程编辑器

曲线连接、带类型端口的节点图。**只有连在流程线上的节点会执行**，画布外孤立的节点不会弹窗、不会导出。

- **中键拖动 = 平移画布。**
- **左键单击 = 选中；左键拖空白 = 框选多选。**
- 左键拖节点 = 移动；多选时拖任意一个会整组移动；Delete 删除选中的全部。
- 滚轮缩放；右键空白加节点；右键节点跳过 / 删除；Alt+左键点圆点删线。

| 节点 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| 源文件 | — | 图像 | 整张皮肤原图 |
| 暂停 | 图像（可选） | 继续、回答 | 提示 / 询问；有图输入时落盘到 `临时/` 供修改，继续时读回 |
| 蓝图 | 图像、字符 | 每个有效 Result 一个输出 + 图组 | 节点高度随 Result 数变化 |
| Make 合并 | 多个图像（数量可设） | 图组 | 把多张图 / 多个组合并成一个组，没连的输入跳过 |
| Break 拆分 | 图组 | 每个结果一个图（数量自动） | 接到图组后自动出现对应数量的输出点 |
| 放大 | 图像 | 图像 | 只放大像素 |
| 重命名 | 图像、Text | 图像 | 命名模式 + 重名加序号；Text 来自接到它的暂停回答 |
| 导出 | 图 / 图组、文件夹名 | — | 文件夹名 = 字符输入；图片用自己的 Result 命名 |

导出节点的字符输入会当成**文件夹名**：

- 没有字符输入：`程序目录/导出/<皮肤文件名>/`
- 有字符输入（暂停里填的“12”）：`程序目录/导出/12/`
- 设了导出根目录：`<根目录>/<字符输入>/`

图片文件名直接用它自己的名字（蓝图 Result 上的命名模板），所以图组里每个 Result 各叫各的。命名模式留空即可；只有想临时覆盖文件名时才在里面写 `{Result}`、`{L}`、`{Text}` 之类。

流程编辑器工具栏里的「打开…」可以导入别人分享的流程 JSON；「目录」直接打开 `workflows/` 方便拿文件。流程里引用到的蓝图是单独的文件，分享流程时记得把 `blueprints/` 里对应的蓝图 JSON 也一起发（蓝图编辑器里同样有「打开…」和「目录」）。

### Make / Break

![Make / Break](screenshots/make_break.png)

- **Make 合并**：节点参数里设「输入数量」（1~16），就会出现 图像1…图像N。每个输入接一张图或一个组，输出一个图组；没连的输入直接跳过，不会拿源文件顶替。
- **Break 拆分**：接一个图组，输出点数量自动跟着上游算：
  - 蓝图图组 → Result 的数量
  - Make → 实际连上的图片总数
  - 单张图 → 1 个输出
- 这样蓝图的单个 Result 也有用了：用 Make 把 result1、result2 合成组再交给导出；或者用 Break 把图组拆开，让每张图单独接重命名 / 放大 / 导出。
- Break 的输出数在打开流程、连线、刷新蓝图和运行前都会重新同步；上游变少时，多出来的输出点会变成空，连在上面的线会被清掉。

### 暂停修改图片

![暂停修改](screenshots/pause_edit.png)

暂停节点接上图像后，暂停时会把当前图（一张或一个图组）写到：

```text
临时/暂停_<流程名>_<节点号>_<时间>/01_名字.png
```

- 节点参数里勾「自动打开」，暂停时会自动弹出这个文件夹；对话框里也有「打开文件夹」按钮。
- 你可以用画图 / PS 改这些 PNG，改完点「继续」，程序会按文件名顺序把图读回来，后面的节点用的就是改过的图。
- 不勾「自动打开」也会落盘，只是不弹文件夹。
- 没有接图像输入的暂停（纯文字询问）不会建文件夹。
- `临时/` 里的东西不会自动删，确认没用了可以手动清掉。

### 重命名的 Text

![重命名的 Text 输入](screenshots/rename_text.png)

重命名节点现在多了一个 **Text** 输入：

- 把暂停（询问模式）的「回答」接到哪个重命名，`{Text}` 就是哪一次的回答。
- 不接就是空字符串，不会去拿别的暂停的回答。
- 所以两个暂停可以各接一个重命名，分别用各自的 Text，互不串：

```text
暂停 A「回答」→ 重命名 1（{Text}_头部）
暂停 B「回答」→ 重命名 2（{Text}_眼睛）
```

导出节点、蓝图节点的字符输入也是同理：各自用各自接进来的文字。

## 蓝图编辑器

左边是箭头节点区：**输入（示例图）→ 画布 → Result**；右边上面是输入与选区，下面是画布 / 矩形 / Result 的属性。

### 输入与选区

- 输入是一张示例图，只用来在设计时拉框参照，**运行时不参与**。
- 在示例图上按住拖 = 新建选区；按住已有选区可拖动，拖右下角改大小。
- 拖动/拉框时**实时吸附整数像素**，不会出现半个像素的选区。
- 右上角「网格」可以开关输入预览和画布预览的像素网格，设置会记住。
- 选区坐标吸附到整数像素；选区自动命名 `选区1`、`选区2`……，可改名，也能直接输入坐标 / 尺寸。
- 顶部「放大」按钮会把示例图铺满整个屏幕来拉框，Esc 关闭。

### 画布、映射和矩形

- 画布尺寸由你输入。
- 画布上方的「素材」下拉里会列出：连到画布上的输入图选区 + 连到画布上的矩形节点里的矩形。
- 点「添加映射」把素材贴到 (0,0)，然后在画布预览里拖动摆位置；X / Y 也能手输。
- 每个映射可以旋转 **0° / 90° / 180° / 270°**：选中映射后用「旋转 90°」按钮或「旋转」下拉；旋转 90/270 时占位宽高会互换。
- 映射列表的顺序就是叠放顺序（后面的盖住前面的），可以直接拖动列表排序，也能用 ↑ ↓。
- 画布区右上角的「放大编辑」会把画布铺满屏幕，方便摆位。
- **矩形节点**：右键空白 → 添加：矩形。节点里可以加多个矩形，每个有名称、宽、高、颜色；矩形节点用橙色端口连到画布，之后就能在画布的「素材」里选到它。
- 一个 Result 只能接一个画布；**有几个有效 Result，流程里的蓝图节点就有几个输出点**，另外永远有一个“图组”输出。

### Result 命名

命名写在 Result 节点上，例如：

```text
{Skin}{"_"}{L}{"x"}{W}{"cm"}
```

- **公用（整次运行 / 整个蓝图节点共享）**
  - `Skin`：皮肤文件名（整次运行固定）
  - `Time`：`202610310303`（整次运行固定）
  - `Date`：`20261031`（整次运行固定）
  - `Text`：流程里“字符”输入（比如暂停问到的名字）；同一个蓝图节点下的所有 Result 共用（重命名 / 导出节点各有自己的 Text 输入，见上面）
- **私有（每个 Result 自己算）**
  - `L` / `W`：这个 Result 对应画布的像素宽 / 高；要厘米就自己乘，例如 `{L*3.75}cm`
  - `Canvas`：这个 Result 接的画布名字（`Name` 在 Result 命名里等同于 `Canvas`）
  - `Result`：这个 Result 自己的名字
  - `Index`：第几个 Result（从 1 开始）
- 运算：`+ - * / %`、括号、`round / int / floor / ceil / abs / str / upper / lower / max / min`
- 字符串用 `"cm"` 或中文引号 `“cm”`；`{_}` 这种纯符号块直接当字面量
- 小写别名也能用：`{text}`、`{skin}`、`{canvas}`、`{result}`、`{index}`，中文别名 `{长}`、`{宽}`、`{时间}`、`{文字}` 等

举例：两个 Result 分别接 32×16 和 8×8 的画布，`Text`=乔然、`Skin`=steve：

```text
Result 1：{Skin}_{Result}_{L}x{W}  →  steve_result1_32x16
Result 2：{Skin}_{Result}_{L}x{W}  →  steve_result2_8x8
```

**注意**：导出文件夹（根目录）里只能用公用变量 `Skin / Text / Name / Time / Date`，不能用 `L / W / Canvas / Result / Index`（那一步还没算到具体 Result）。

## 全屏编辑

![全屏选区](screenshots/full_input.png)

示例图和画布都能全屏编辑：左边大图，右边保留列表、坐标、宽高、颜色等属性。**滚轮缩放、中键拖动画面**；Esc 关闭后自动同步回蓝图。

蓝图的工具栏也有「打开…」和「目录」：可以导入别人分享的蓝图 JSON，也能直接打开 `blueprints/` 拿文件分享。蓝图 JSON 里的示例图是可选的，分享时没带示例图也能正常运行，只是设计时没有参照图。

## 导出

- 字符输入 = 文件夹名；图片按自己的 Result 命名。
- 命名模式留空 = 用图自己的名字（蓝图的 Result 命名）。
- 同名默认跳过，可勾“同名覆盖”。
- 设置里选“填充颜色”时，导出会把透明区域压到所选背景色；默认保留透明。

## 打包成 exe

已经构建好一版 **文件夹版**：

```text
dist\BLUE\BLUE.exe
dist\BLUE_3.0.4beta_win64.zip   （整个文件夹的压缩包，分享用这个）
```

onedir 不会把程序解压到系统临时目录，避开了 onefile 常见的
`Could not create temporary directory!` / `Failed to create parent directory structure`。
**分享和移动时要带上整个 `BLUE` 文件夹，不能只拿 exe。**

想自己重新构建：

1. 装 Python 3.10+，安装时勾选 **Add python.exe to PATH**。
2. 双击 **`build_exe.bat`**，生成：
   ```text
   dist\BLUE\BLUE.exe
   ```
3. 也可以手动：
   ```bat
   pip install -r requirements.txt
   pyinstaller --noconfirm --clean --onedir --windowed --name BLUE ^
       --icon app.ico --version-file version_info.txt skin_head_gui.py
   ```

- 第一次运行会在 `BLUE.exe` 旁边生成 `workflows/`、`blueprints/`、`临时/`、`导出/` 和 `skin_head_settings.json`。建议整个文件夹放在可写位置（不要直接放 Program Files）。
- 图标在 `app.ico`，版本信息在 `version_info.txt`。
- Windows 可能提示“未知发布者”，选“更多信息 → 仍要运行”。
- 如果 exe 被 Windows 的应用控制 / Device Guard 策略拦截，双击包里的 **`启动 BLUE（源码）.bat`**（需要 Python 3.10+，会自动装 Pillow），效果一样，数据也写在旁边。
- 如果确实想要单文件，可以自己加 `--onefile` 试试；但部分机器会因临时目录权限报上面那个错，所以默认用文件夹版。
